# M9 界面与教学体验

M0–M8 已完成场景、几何、绘制/编辑、工程量、测量与文档能力。M9 不改动任何几何算法与工程数据口径，只重做界面结构与教学反馈：三列工作区、集中管理的工具与删除入口、状态栏、输入范围与错误表达、禁用原因说明、响应式与键盘可达性。

## 本阶段交付

- **三列工作区** `src/components/SceneViewport.tsx` + `src/app/App.tsx` + `src/app/styles.css`：`main.workspace` 改为 CSS Grid `150px / minmax(0, 1fr) / 320px`，顶部 `DocumentBar` 与底部 `.bottom-bar` 都用 `grid-column: 1 / -1` 横跨整行。中间场地用 `minmax(0, 1fr)` 保证可收缩，因此任何宽度都不会横向溢出。
- **左侧施工工具** `src/components/ToolPanel/ToolPanel.tsx`（新）+ `toolLabels.ts`（新）：工具切换（`aria-pressed` 表达当前工具）与删除当前对象。原来分散在 `DrawingPanel` 里的工具按钮组与其文案常量一并迁出，`TOOL_LABELS` / `TOOL_HINTS` 成为界面上唯一的中文来源，状态栏与工具按钮共用。
- **状态栏** `src/components/StatusBar/StatusBar.tsx`（新）：始终以文字显示当前工具、俯视光标的地面坐标（取整到厘米，指针离开画布显示 `—`）、网格与吸附开关、当前工具的操作提示、开挖对象数与保存状态（`已保存` / `未保存` / `正在保存或打开…`）。状态栏只读取已有界面状态、不触发任何命令，也不用颜色表达状态。
- **输入范围与错误表达** `src/components/PropertyPanel/NumberFields.tsx`（重写）+ `PitEditor.tsx` + `TrenchEditor.tsx` + `DrawingPanel.tsx`：输入框带 `min`/`max` 与`取值范围 …～…`提示；被拒绝时加 `aria-invalid` 并通过 `aria-describedby` 关联中文原因，模型保持上一有效值。`min`/`max` 只作界面提示与浏览器辅助，数值是否接受仍由 `core/validation` 决定。
- **禁用原因说明** `ToolPanel` / `ViewControls` / `DocumentBar`：所有不可用操作都禁用并在 `title` 写出原因——未选中对象时的删除入口、绘制与放置期间被锁定的视角、还没有开挖对象时的显示模式、保存/打开等待期间的全部编辑与文件操作、历史为空时的撤销/重做。
- **响应式与可访问性** `src/app/styles.css`：宽屏三列；≤1180px 工具面板转为横排工具栏、场地与参数并排；≤800px 全部单列堆叠。操作元素全部是原生 `button`/`input`/`select`，沿用 `:focus-visible` 聚焦环；输入法组合（`isComposing`）中的按键不触发场景命令（M5 已有，M9 补界面级验证）。

## 键设计

| 关注点 | 做法 |
| --- | --- |
| 状态栏与既有状态元素不冲突 | 状态栏用 `role="group"` 而非 `status`，避免与 `.scene-status` 争夺唯一的 `role="status"`；文字统一加前缀（`保存状态：未保存`），不与文档栏徽标的精确文本冲突 |
| 不重复同一提示 | 草稿读数与吸附来源只留在参数面板；状态栏显示的是*当前工具的操作提示*，因此同一句话在界面上只出现一次 |
| 单一中文来源 | 工具名称与操作提示集中在 `components/ToolPanel/toolLabels.ts`，避免状态栏与按钮文案漂移 |
| 不新增第二套业务校验 | `NumberFields` 的 `min`/`max` 只用于提示与浏览器辅助；接受与否仍由 `core/validation` 判定，字段定位按 `issue.path` 末段匹配 |
| 光标坐标不引起无意义重渲染 | `trackCursor` 只在俯视且取整到厘米后的坐标发生变化时才 `setState`；切视角与指针离开画布都清空 |
| 布局不产生横向滚动 | 中间列用 `minmax(0, 1fr)`；断点只改变排列顺序，不改变任何交互或数据行为 |
| 不做视角过渡动画 | 手册列为可选；动画会干扰 jsdom 测试中的投影正确性与画布拾取，且需求优先级是"几何正确 > 数据正确 > 交互可用 > 工程保存 > 视觉美观" |

## 验证

`npm run check` 全绿：**17 文件 237 项测试**（`tests/app.test.tsx` 从 44 增至 49，新增 5 项 M9 界面测试），并完成 build 与 smoke。

新增的 M9 界面测试（`describe('M9 界面与教学体验')`）：

- 状态栏显示工具/坐标/网格/吸附/对象数/保存状态；切到俯视后指针移动得到地面坐标，移到画布外清空；网格与吸附开关以文字同步；绘制后对象数与保存状态随之变化。
- 左侧工具面板可切换工具（`aria-pressed`），无选中时删除按钮禁用、`title` 与可见说明给出同一原因；放置并选中对象后按钮改名为`删除当前基坑`并可用，删除后回到禁用态。
- 属性输入带 `title=取值范围 0.02～1000` 与 `min`/`max`；输入 `0` 被拒绝后字段 `aria-invalid="true"` 且出现中文原因、对象数不变；改回合法值后标记与提示同时清除。
- 绘制期间`自由视角`等按钮禁用且 `title=绘制期间锁定视角`，`Esc` 取消后恢复可用并回到常规说明。
- 工具与视角按钮可聚焦，无节点时 `Enter` 只提示不产生命令；输入法组合中的 `Enter` 被忽略。

回归：M1–M8 的 232 项测试全部保持通过，原有查询约定（`getByRole('status')` 唯一、`getByText('已保存'/'未保存')`、删除按钮名、`getByText(/N 个开挖对象/)`）未被破坏。

真实浏览器（Chromium）：

- 页面加载无控制台报错、无失败请求；三列工作区、`施工工具`、`场景显示控制`、`状态栏` 均存在且可见；状态栏包含全部要求的前缀文字。
- 当前浏览器工具只提供 834×794 视口，无法强制切到 1280×720 / 1920×1080；在该宽度下 `scrollWidth (819) ≤ innerWidth (834)`，无横向滚动条、无元素重叠或裁切，且已进入 `≤1180px` 断点（工具面板横排、两列）。1280×720 与 1920×1080 走的是基础三列分支，其列宽与内边距按上述栅格数学推算不会溢出，但未在本轮做真实渲染截图验收。
- 点击`绘制基槽`后按钮进入选中态、底部`自由视角`变为禁用、状态栏`工具：`同步为`绘制基槽`；`Esc` 恢复。

## 已知取舍与后续

- 未实现四视角之间的过渡动画（手册列为可选）；如后续要加，需要先让测试不再依赖"切视角后投影立即正确"的假设。
- 窄屏（≤800px）下场地与参数纵向堆叠，需要滚动查看；本轮未做移动端专用的折叠面板。
- 1280×720 / 1920×1080 只有 CSS 栅格推算与 ≤1180px 断点的实测，没有两档分辨率的真实截图证据；M10 用 Electron 窗口尺寸固定后再补一次端到端验收更合适。
- 状态栏坐标只在俯视图显示；自由视角下视线与地面交点不可靠，因此显示 `—`。
- 保存等待期间的并发编辑仍是"直接拒绝并提示"（M8 的保守做法），未改为只读提示 + 队列。
- Electron 窗口、受限 IPC、原子写盘与 Windows Portable 打包属 M10。
