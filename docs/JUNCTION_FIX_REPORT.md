# 沟槽接口真实贯通修复

日期：2026-09-24。用户确认采用“真实挖通，并同步修正土方量”，不采用仅隐藏面片的视觉补丁。

## 根因与可重复证据

旧 `MeshFactory.abuttingEnds` 只检查端部两个顶部角点接触相邻轮廓，再设置 `openStart/openEnd` 删除支槽端面。主槽坡面未裁，连接底侧面未补。

40m方环、底宽2m、深2m、坡比0.5；支槽中心线 `(20,10)→(20,38)`：环槽顶部内边 y=38、底部内边 y=39。深度 z=-1 处保留宽0.5m土楔，槽底缺1m。旧实现有限射线实测：

- `(20,37,-1)→(20,40,-1)` 没有命中；
- 反方向命中主槽坡面 `(20,38.5,-1)`。

FrontSide 材质从背面不显示这堵坡墙，导致一边看通、另一边不通。旧测试仅从一侧射向远墙，且错误地把土楔解释成重叠。`M5_REPORT.md` 已勘误；保留历史修复记录，但不再沿用其连通性结论。

## 修复约定

1. 保存的节点、底宽、深度、坡比不改写。连接是可重复派生的几何，修改/移动/删除任一邻槽会重算。
2. 支槽端面必须完整贴在**同一邻槽、同一条边**上，且延伸方向进入邻槽，才认定接口。两角分别接触不同对象不算连接。
3. 支槽原端断面沿中心线延伸至对应主槽线段的中心线；环形槽连接对应的局部线段，不连接环形中心。
4. 派生连接顶轮廓必须包含在原邻槽开口中，不扩张地面开口；原主体仍按现有规则拒绝内部交叠。
5. 普通段和环形段按 miter 截面分成凸单元。每个单元验证凸性、面共面性及有限数值。
6. 凸单元相互裁剪内部面；相反的公共墙两侧均删除，同向重合外表面只保留稳定归属的一份。底面与边坡材质组、对象ID、选择高亮仍保留。
7. 深浅槽在共同深度内贯通，较深区域保留真实台阶和封口，不整端挖空。
8. 保持 FrontSide，不调整光照或用 DoubleSide 掩盖缺面。不新增第三方依赖。
9. 删除旧 `openStart/openEnd` 单独删端面的入口，避免后续代码绕过连接算法再次制造假连通。

## 模块与维护入口

| 模块 | 责任 |
| --- | --- |
| `core/geometry/convexExcavation.ts` | 纯数值凸体、半空间裁剪、共面归属、三角化和有向体积；只在渲染边界转Float32 |
| `core/geometry/trenchNetwork.ts` | 识别端部贴合、构造派生连接、稳定排序、输出按对象ID分组的并集面片及修正量；有界单结果内容缓存 |
| `scene/MeshFactory.ts` | 使用合并面片渲染连接对象；独立对象保持原生成器，中心线仍来自保存数据 |
| `scene/groundTriangulation.ts` | 正常使用带孔三角化；接触轮廓出现非空但面积错误时，以外部凸片减去孔洞三角片回退，主地面与岛面共用面积守卫；不扰动坐标 |
| `core/calculation/quantities.ts` | 单槽读数保持原设计估算，项目总量加 connectionCorrection |
| 属性面板/工程量合计 | 明示“单槽设计估算”和“连接补充开挖”，不把修正藏在节点长度中 |

纯数值并集只针对当前直线/折线/环槽的平面坡面结构，不是任意实体 CSG。面片积分保持有向符号，不逐三角取绝对值；积分原点仅在XY平移，z=0虚拟顶盖贡献为0。

## 土方量合同

`项目合计 = 原有单对象估算之和 + (连接后并集体积 − 连接前对应凸单元体积之和)`。

这样不重复累加延伸段与原主槽重叠的体积，也不改变无连接对象的计量方式。单槽折线的原教学估算限制仍存在，不能把本次改动称为专业工程计价。

标准正交 T 接口：B=2、H=2、m=0.5。深度 d 的支槽宽度为 `4-d`，未挖土楔长度为 `0.5d`，所以补挖量为：

`∫[0,2] (4-d)×0.5d dd = 8/3 m³`。

40m方环加28m支槽：旧合计1128m³；修复后1130.666666…m³。相同零坡比接口增量为0；深浅槽按实际并集产生台阶和相应增量。

## 边界与使用提示

本次处理端部对侧边、端部对端部的完整贴合接口。仅角点接触、斜接只有单角贴边、平行槽口并排贴边，不能仅凭顶部接触宣称槽底贯通。若接口过于靠近转角，导致延伸断面超出邻槽原顶口，也不擅自扩大开口。需要一般斜交或任意交叉开挖时，应另行扩展开口合并与连接数据合同。

几何裁剪有面片数量安全上限；当前对象数量上限不等于最坏复杂网络的性能保证。文件保存、撤销仍属于后续阶段，本次未扩展。
