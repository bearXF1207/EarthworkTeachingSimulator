# M2 验证报告

日期：2026-09-22。范围：M2.1 方形、M2.2 矩形、M2.3 圆形全部完成；不包含 M3 基槽。

## 实现入口

| 文件 | 职责与后续执行方式 |
| --- | --- |
| `src/core/model/project.ts` | version=1、米单位、设置、四类元素联合、Result/ValidationIssue；基槽仅数据合同 |
| `src/core/validation/project.ts` | 接收 unknown，检查类型、有限数值、上下限、ID、顶部边界及开口冲突；成功后重建白名单纯JSON字段并归一化角度 |
| `src/core/geometry/pit.ts` | 共用方/矩形环生成器及96段圆环，输出非索引三角形几何、顶/底轮廓；仅底面和内向边坡，无顶盖 |
| `src/core/geometry/pitOutline.ts` | 纯数值轮廓计算；校验和 store 不依赖 Three 运行时，Mesh 生成器复用同一轮廓 |
| `src/store/ProjectStore.ts` | add/update/delete/grid 命令；候选校验→注入的 prepare 生成资源→同步 commit→更新数据，异常返回中文错误 |
| `src/scene/MeshFactory.ts` | 底面与边坡不同材质，默认 FrontSide；线框切换和幂等释放 |
| `src/scene/GroundManager.ts` | ShapeUtils 带孔三角化，核对三角形总面积；1m网格逐线减去开口区间；默认100m、轮廓外扩至少10m |
| `src/scene/SceneManager.ts` | prepareProject 返回 commit/dispose；候选完成前不触碰旧场景；替换后释放旧地面、网格、坐标轴与基坑 |
| `src/components/PropertyPanel/PitEditor.tsx` | 数字文本草稿与已接受工程分离；合法修改即时提交；圆形没有旋转字段 |
| `src/components/SceneViewport.tsx` | 演示创建、对象下拉、参数编辑、删除、显示模式及资源重载 |

实施手册中的方形/矩形/圆形生成器暂合并到同一模块，避免重复三角面代码；命令类型与最小 store 暂同文件。M3 扩展此入口，禁止绕过校验直接修改 Scene 或 React 的工程数组。M8 在此加入历史；当前没有撤销、保存或反序列化 UI。

`dispatch(command, prepare)` 的第二个参数是可替换的场景适配器。prepare 只创建候选；commit 仅同步交换已经构建好的资源，不再执行几何运算或异步操作；取消候选调用 dispose。快照使用深拷贝，调用方不能持有 store 内部引用。

## 自动化验证

执行 `npm run check` 成功：TypeScript、ESLint（零警告）、Vitest、生产构建及 dev/preview HTTP 冒烟全部通过。共5个测试文件、41项测试；原M1回归仍保留。

- 三类坑的顶部尺寸、底部尺寸、标高、圆环96点与矩形90°世界包围盒。
- 所有顶点/法线有限，逐三角形检查面积、内向边坡及向上底面，不存在顶盖；采用非索引几何，因此没有独立 index 缓冲。
- 射线穿过顶部开口且命中 FrontSide 坑底；地面总面积为外边界减孔面积；网格不跨方坑开口。
- 圆孔与旋转矩形同时开孔，孔心没有地面遮挡、孔间仍有地面；移动后旧位置回填，新位置开孔；偏心场地外扩边距正确。
- 0、负数、NaN、Infinity、null、字符串及空字符串深度均拒绝；非法尺寸、越界、重复ID、501对象和当前未实现的基槽拒绝。
- 坡比0合法，角度归一化；方坑间距7m可接受、6m相切及5m重叠拒绝；包含、圆–多边形以及圆圆 π/96 方向相切回归。
- 命令校验失败不调用prepare；构建失败保留旧快照；深拷贝隔离；缺失对象删除拒绝。
- 强制实际地面三角化返回空结果时，候选坑释放，旧场景不释放且快照不变，渲染循环保持活动。
- 界面三类型创建、编辑、非法草稿、重载保留项目、删除及单一渲染循环。
- 实际 SceneManager 在替换 GPU 边界的测试中连续更新100次：每次释放4个几何和5个材质，累计400/500；取消候选与卸载继续准确释放，不留下旧资源。

构建主JS约801kB（gzip约216kB），仍有超过500kB的体积提醒。它不是类型、lint或测试失败；未新增依赖，未修改阈值掩盖问题。

## 真实浏览器验收

在本地开发服务、真实 WebGL 画布中操作，而非截图替代模型：

1. 连续创建三类坑，俯视放大确认三种底面和边坡可见，网格在孔边停止。
2. 自由视角确认坑底位于地面以下，边坡朝向正确；地面不是透明平面。
3. 圆坑X从12改为6，与原点矩形冲突，出现中文拒绝原因；切换对象再返回，X仍为12。
4. 矩形旋转90°；圆坑连续编辑深度100次，再将坡比设为0，前视线框可见竖直边坡与负Z深度；侧视方向正确。
5. 删除圆坑后俯视检查原孔恢复为完整地面和网格，其余两坑保持可见。

真实浏览器的100次更新确认交互仍正常；资源数量稳定由上述释放计数回归验证，未将其夸大为实际显卡显存测量。坐标轴为独立辅助线，可能经过开口；1m场地网格已按孔裁剪。

## 已知边界

- 初始镜头仍按100m场地取景；小坑需滚轮放大。场地随孔洞自动扩展，但镜头不自动跟随远处对象。
- 演示对象按固定12m间距排列，用户编辑后可能与下一演示位置冲突，此时拒绝创建并说明原因；不是正式鼠标放置功能。
- 工程只在内存中；“重新加载场景”保留工程，浏览器刷新不保留。不得将当前版本当作可保存成果的生产应用。
- 每次有效参数变化重建全部坑与地面，当前通过小规模和100次重复更新验收；500对象限额不是最坏场景性能保证。
- 前/侧正交视图不是剖面，实体遮挡坑底是正确现象；可用线框检查轮廓。
- `PROJECT_SPEC.md` 是工作区已有未跟踪文件，本次保持原样且不纳入提交。
