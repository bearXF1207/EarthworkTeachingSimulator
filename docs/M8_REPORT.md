# M8 项目文件、未保存状态与 50 步撤销重做

M0–M7 已完成场景、几何、绘制/编辑、工程量与测量。M8 补齐"工程能存下来、改动可回退"的文档能力：文件格式与严格校验、打开/保存/另存为、dirty 基线与离开提醒、50 步撤销重做。

## 本阶段交付

- **项目文件（`.excavation`，version 1）** `src/core/io/projectSchema.ts`：`serializeProject` 稳定序列化（字段顺序固定、无 Scene/Mesh/相机/选中状态），`parseProject` 严格反序列化——先查大小/JSON/version/units/name/settings，再逐字段白名单重建（未知字段忽略、缺字段与未知类型拒绝、重复 id 拒绝、节点数与对象数超限拒绝），最后交给 `validateProject` 做数值/拓扑/开口校验。**失败不替换当前工程**（不是先清空再逐个试）。
- **文件服务合同** `src/core/io/fileGateway.ts`：`FileGateway.open/save` 与 `SaveOutcome = saved | cancelled | export-requested`。浏览器适配器优先 File System Access（可写回原文件并复用目的地），缺失时回退 file input + 下载副本；下载只能报告"已请求导出"，UI 另有独立的**确认已导出**。
- **50 步撤销重做** `src/core/commands/commandManager.ts` + `ProjectStore`：只记录已提交的文档快照，新动作清空重做分支；**准备几何失败不移动历史栈**（`peek`/`commit` 分离）；无变化命令（参数改回原值、重复设置同一开关）与失败命令都不占历史。
- **dirty 基线**：`revision + 稳定序列化文本`双重判定。保存成功或用户确认导出后把**被写入的那份文本**设为基线；撤销回保存内容即恢复干净，重做后再次变脏；保存等待期间若文档被修改，不会被误标为已保存。
- **界面** `src/components/TopBar/DocumentBar.tsx` + `src/components/dialogs/UnsavedDialog.tsx`：新建/打开/保存/另存为、撤销/重做、保存状态徽标、`确认已导出`；未保存时新建/打开弹出"保存 / 不保存 / 取消"三选项；保存失败、取消或仅请求导出都不会继续清空工程。`Ctrl+Z` / `Ctrl+Y`（含 `Ctrl+Shift+Z`）在画布生效，焦点在输入框时保留文本编辑行为；`beforeunload` 仅在 dirty 时触发浏览器原生提醒。
- **打开/新建是新会话**：原子替换项目、清空历史与草稿、清空选择与临时测量、按新设置同步网格/吸附开关；打开失败保留整个当前状态。

## 键设计

| 关注点 | 做法 |
| --- | --- |
| 原子加载 | 校验与资源准备全部成功后才替换项目；失败保留原会话与原历史 |
| 历史与几何 | 撤销/重做复用 `prepareProject` 入口，不复用已 dispose 的 Mesh；被撤销掉的对象不会保持选中 |
| 无变化命令 | 用稳定序列化比对候选与现状：相同则不入历史、不重建几何、不改 revision |
| 保存口径 | 只有 `saved`（真实写入）或用户明确确认导出才更新基线；`export-requested` 与取消都保持 dirty |
| 并发保护 | 保存/打开等待期间禁止文档编辑（返回明确提示），避免确认错快照；`ErrorBoundary` 兜底渲染异常 |
| 设置属于文档 | `gridVisible` / `snapEnabled` 是可保存的工程设置，因此它们走命令入口、可撤销并计入 dirty |

## 验证

`npm run check` 全绿：**17 文件 232 项测试**（新增 25 项：项目文件 7、历史与 dirty 8、文件服务 5、界面 5）。

单元与集成：

- 往返：三类基坑 + 直槽 + 折线槽保存再打开后参数、id、位置、旋转、设置与预计体积一致，文本逐字节稳定，且不含 `Mesh/geometry/material/Scene/camera/selected`。
- 拒绝路径：非法 JSON、空文件、超大输入、缺 version、version=999、units='mm'、空 name、未知类型、重复 id、501 个对象、201 个节点、非有限字段、错误 settings、自交中心线、重叠开口；`load` 失败后工程与历史保持不变。
- 历史：创建→改参数→移动→删除逐步撤销/重做一致；51 次编辑只保留最近 50 步；撤销后新编辑清空重做；无变化/失败命令不占历史；准备失败不移动栈。
- dirty：新工程干净 → 编辑变脏 → 保存干净 → 编辑脏 → 撤销回保存内容干净 → 重做再脏；保存期间并发编辑不会被误标为已保存。
- 文件服务：句柄写回并复用目的地；取消返回 `cancelled`；写入失败返回外层错误；无句柄时只请求下载并返回 `export-requested`；取消文件选择解析为 `null`。

真实浏览器（Chromium，真实鼠标/键盘）：

- 绘制后徽标为"未保存"；无真实用户手势时 `showSaveFilePicker` 被浏览器拒绝 → 界面提示"保存失败"且**保持未保存**（失败不清 dirty）。
- 下载回退：保存 → 请求导出 + 出现"确认已导出" → 确认后变"已保存"；抓取实际导出的 Blob 内容为合法 v1 工程（`version=1`、`units=m`、2 个对象、4 项 settings）。
- 往返：把导出的文本重新注入文件选择（改动 name）→ 打开后名称、对象数、已保存状态一致。
- 拒绝：`version=999` 的文件 → 提示"不支持的项目版本 999…请勿用旧版打开未来格式"，当前工程完整保留。
- 未保存对话框：三选项齐全；取消保留 3 个对象；不保存并继续进入新会话（0 个对象、已保存、撤销按钮禁用）。
- 快捷键与基线：`Ctrl+Z` 撤销回打开时的内容 → 徽标变"已保存"；`Ctrl+Y` → 再次"未保存"；`beforeunload` 仅在 dirty 时被阻止（clean 时不阻止）；全程无 window error。

## 已知取舍与后续

- 浏览器阶段只用 `beforeunload` 原生提醒，无法自定义关闭对话框；完整"关闭前保存"流程属 M10（Electron）。
- 无文件句柄能力时"保存/另存为"只请求下载副本，不声称覆盖原路径；导出后的写入结果由用户点"确认已导出"确认，确认时必须仍与刚导出的快照一致。
- 历史按**文档快照**计数（最多 50 步），不保存文件句柄；打开/新建不算可撤销命令。
- 网格/吸附开关计入 dirty 与历史（它们是保存的工程设置）；如后续希望它们不参与文档历史，需要先从文件 schema 移出。
- 保存期间禁止编辑是阶段内的保守做法；M9 可改为"保存中只读提示 + 队列"，但必须保持"确认的是同一份快照"。
- 与 Electron 相关的能力检测、受限 IPC、原子写盘与 Windows Portable 打包属 M10。
