## 核心设计说明

- 工具状态是判别联合，每种工具只保留自己的临时数据；切换工具、`Esc`、取消都会清空上一工具草稿。草稿不进入 `Project.elements`、历史或文件，只有成功完成/放置才派发一次 `add` 命令。
- 投影使用画布自身 bounding rect（不是窗口宽高）；越界与零尺寸直接返回 null。视线与地面接近平行时（`|n·d| < 1e-9`）交点会漂移到远处，同样按无交点处理，并与“只有俯视用于地面绘制”的视角判断形成双重保护。
- 双击分三层处理：忽略 `detail > 1` 的 click；忽略与末节点重合的位置；`dblclick`、`Enter` 与“完成基槽”按钮共用同一个 `finishTrench` 校验提交函数，不依赖最终校验去兜底重复点或生成半个对象。
- 拖动判定：`pointerdown` 与 `click` 之间位移超过 3 CSS 像素即按平移处理，因此绘制期间的平移与缩放不会落点。
- 精确输入按绝对方位角推算 `q = (p.x + L·cosθ, p.y + L·sinθ)`，θ 正规化到 `[0,360)`，结果**不做吸附**，长度不会被改写；鼠标点先投影到地面再按每轴 `Math.round(v/1)*1` 吸附，结果归一化 `-0`。
- 快捷键保护：`input/textarea/select/contenteditable` 以及 `isComposing`/`keyCode 229` 都不触发场景命令；输入框内 `Enter` 只提交输入段，`Esc` 不取消草稿，`Ctrl+Z` 仍归文本编辑。
- 预览与提交同源：预览折线来自同一草稿状态，基坑预览由 `pitFromDraft` + 槽顶轮廓生成，与提交使用同一个构造函数，避免预览与结果字段不一致。
- 进入绘制/放置工具自动切到俯视并锁定视角按钮，取消或完成后恢复进入前的视角；选中新对象，预览资源立即清空。

### 设计说明

- 吸附目标按类型提供：`node`（中心线节点，端点对接）、`centerline`（中心线线段，对齐与 T 形参考）、`flush-line`（槽顶边界向外平移**新槽顶半宽** `T=B/2+H·m` 后的贴合线，边对边贴合）、`boundary-corner`/`boundary-edge`（槽顶边界角点与边）。默认半径 1.5m。
- 选择规则：先取最近目标，距离并列时按类型优先（节点 > 中心线 > 贴合线 > 边界角点 > 边界边）；端点与角点带 0.4m 等效距离优惠，避免端面边界边压过端点本身。没有目标时回退 1m 网格；关闭吸附时完全不吸附。
- 贴合线是“边对边贴合”的关键：中心线落在 `边界 + T` 上时，新槽的槽顶边界正好与相邻基槽共线，因此只共边不交叠，可直接被校验接受。
- 正交模式：只约束鼠标绘制，按相对上一节点的位移取水平或竖直（相等取水平），锁定的轴不再吸附、网格兜底也只吸附自由坐标；长度/角度精确输入仍按输入值，不静默改写用户角度。
- 闭合连接采用的模型：基槽之间只允许**边界接触**（共边、共点、端面贴合），内部交叠仍拒绝。四段围合时每个转角只归一段所有（例如底段贯通两个下角、右段贯通右上角），即可用只共边的方式围成完整封闭区域；被围合的岛仍是地面。
- 允许接触后地面三角化仍然成立：共边孔洞的总面积等于各孔面积之和，earcut 给出的实际面积与期望值差值在 `1e-6m²` 以内，孔内无覆盖、岛被覆盖、网格只裁剪槽内区间。无需引入布尔运算或 CSG（与设计约定一致）。

### 边界与取舍

- 转角相接需要把相邻槽的交叠部分做并集（实体 CSG），本期不做：转角请并入同一条折线基槽。T 形/十字贯通在本期仍会被拒绝（后续《吸附到中心并贯通》一节已通过“中心吸附 + 自动收边”支持）。因此“围合成封闭区域”需要在四个转角上按“一角归一段”的方式布置（贴合线与角点吸附会引导到位），此时各段只共边，视觉上完全闭合。
- 共边/围合属于 earcut 的退化输入：四段围合时岛内可能出现零面积级的重复三角形（总面积校验通过、可见结果正确）。彻底消除需要自写并集三角化，列入后续优化。
- 正交模式只作用于鼠标绘制；长度/角度输入保持显式角度（沿用“精确输入不吸附”的既有约定）。
- 吸附是固定 1.5m 地面半径，不随缩放变化；吸附目标只取相邻**基槽**，不含基坑。
- 边界边吸附本身会让中心线压在相邻槽边界上而形成交叠，会被校验拒绝并给出指引；实际贴边请使用贴合线（自适应新槽顶半宽）。

## 追加修复：吸附闭合后双击/回车无法确认（2026-09-22）

现象：基槽吸附闭合正常，但双击或按 Enter 时系统似乎“不识别”，不生成对象。

### 复现与根因

在真实浏览器 + 断点跟踪下复现并定位到四类原因（前两类是功能性缺陷，后两类是可用性缺陷）：

1. **“精确相切”被浮点噪声判成内部交叠**：`nextPoint` 用 `cos(270°) = -1.8e-16` 推算下一点，中心线因此不是数学上严格竖直，与相邻槽端面之间产生约 1e-16 的微小交叉。`properCrossing` 用严格符号判定，于是把闭合判成“内部交叠”并拒绝；即使绕过该判定，地面三角化也会因近乎重合的孔洞边产生退化碎片而抛“几何构建失败”。两种情况都表现为“确认没反应”。
2. **端部附近吸附偏向中心线**：点目标（端点/角点）只带 0.4m 等效距离优惠，鼠标落在端点外 0.4～0.8m 时会吸附到相邻槽的**中心线**，新槽开口与邻槽内部交叠，同样被拒绝。
3. **确认路径读取渲染闭包快照**：`finishTrench`/`cancelDrawing`/`advance`/落点解析都用渲染时的 `draw`，同一帧内“落点后立刻 Enter/双击”会读到旧草稿（少最后一个节点，甚至直接提前返回）；“完成基槽”按钮被聚焦时按 Enter 会同时触发全局确认与按钮点击，第二次确认会重复提交。
4. **失败原因与确认方式不易发现**：拒绝原因渲染在绘制面板底部，输入框内 Enter 只提交本段（原设计）却没有引导，用户容易理解为“确认无效”。

### 修复

- `nextPoint` 只把**轴向方向分量**归整为精确的 `0/±1`，非轴向分量原样保留（斜向长度仍精确）；`properCrossing` 改为面积量级容差比较，`edgeProbesInside` 改为多档采样（1e-3、1e-4），使亚微米偏差按接触处理、1mm 级条带交叠仍被识别；`GroundManager` 跳过面积 ≤1e-9 m² 的退化碎片，总面积守卫保留。
- 端点/角点的等效距离优惠由 0.4m 提到 0.8m：鼠标在相邻槽端部附近稳定吸附“端点”，得到只共边的合法闭合。
- 确认、取消与落点解析全部改读 `DrawingManager` 的实时状态，视角判断改读相机实时模式；重复触发自然成为空操作。

## 追加需求：中心线首尾闭合的环形基槽（2026-09-22）

现象：把基槽中心线首尾吸附闭合后仍然无法确认，生成不了基槽。

### 根因（三处，均已复现）

1. **吸附目标里没有草稿自身的起点**：`trenchSnapTargets` 只收集“已存在的相邻基槽”，草稿自己的起点不参与吸附，用户无法精确闭合，只能靠网格凑近似位置。
2. **校验层把闭合当错误**：末点复首点被判为“重复节点”，首段与末段（互为相邻）被判为“相交、接触或共线重叠”。
3. **几何层不支持环**：轮廓仍按“左侧正序 + 右侧倒序”拼成一个自交环，`ringConflict` 报“轮廓自交”；环形截面（外圈 + 内圈）在实体与地面开孔上都没有实现，地面孔洞也不支持嵌套。

### 修复

- **吸附**：新增 `ring-close` 目标（草稿节点 ≥3 时把起点纳入吸附，等效距离优惠 1.2m 高于其它点目标），提示“吸附到起点：首尾闭合，确认后生成环形基槽”。
- **校验**：`isClosedRing` 识别末点≈首点并写入规范坐标（末点严格等于首点）；环形下允许该重复点、首末段视为相邻，其余规则不变；几何异常仍结构化报错。
- **几何**：`trenchOutlines` 对闭合中心线走 `ringOutlines`——每个节点都用 miter 转角、没有端面；外圈/内圈各是一个闭合环（按面积判定谁在外，和绘制绕向无关），并检查四圈各自简单、内圈整圈落在外圈内、内外圈无真交叉、坡比>0 时顶环包住底环。`buildAnnularSolid` 生成环形实体：底部是“外圈减内圈”的 earcut 环形面，外圈与内圈各一圈侧面（内圈反序，侧面背向岛、朝向槽内）。
- **地面**：外圈作为孔洞，内圈作为岛补回一块共面地面补片（`ground-island`），总面积守卫仍按外圈计算。
- **界面**：面板显示“已首尾闭合：确认后生成环形基槽……”，并提示“把最后一个节点吸附回起点即可围合成环形基槽”；确认入口（双击/Enter/Ctrl+Enter/按钮）完全复用。

### 验证

`npm run check` 通过：**9 文件 139 项测试**。新增环形用例覆盖：末点复首点的闭合判定、20m 见方环的四圈精确坐标（顶半宽 2 → 外圈 24²/岛 16²，底半宽 1 → 22²/18²）、环形实体有向体积 = 棱台体积 480 且内外圈侧面法向朝向正确、环内圈翻折与八字自交被拒绝、地面外圈开孔 + 岛补片（射线命中与面积守恒）、平行贴边可接受而岛内放置被拒绝、闭合吸附优先级，以及界面流程“四点单击 + 吸附回起点 + Enter 生成单个闭合对象”。

真实浏览器验收：绘制 20m 见方回环，末点吸附回起点时提示“吸附到起点：首尾闭合”，用**真实 Enter** 确认后生成 1 个开挖对象（节点 `(0,0)(20,0)(20,20)(0,20)(0,0)`），俯视图可见环形开口与中间的岛；另用纯函数复核“环形基槽 + 邻近三角形环”不冲突，而槽带真实相交时按既有规则拒绝并给出指引。

### 边界

- 环形基槽按外圈参与开口冲突判定：内圈岛内暂不允许放置其它开挖对象（地面开孔不支持嵌套孔洞，需要孔中岛时会破坏三角化）。
- 网格线不跨越岛（岛只有地面补片，没有网格线），属已知简化。
- 属性面板编辑末点会解除闭合，环形自动回退为开口折线；环的最小不重复节点数为 3。

## 追加需求：吸附到中心并贯通 + 中心线常显高亮（2026-09-22）

### 1. 已建基槽的吸附改为“吸附到中心”，并让多条基槽相互贯通

原行为：吸附目标里除中心线骨架外还有**槽顶边界角点/边界边/贴合线**，鼠标落在可见槽带边缘时会吸附到边界；从相邻槽边界起画得到的只是“并排贴边”，想画成十字/T 形贯通则因为开口内部交叠被拒绝。

改动：

- **吸附层重构**：`trenchSnapTargets` 只收集相邻基槽的**中心线骨架**（节点 + 线段），并给每个目标带上对方槽顶半宽 `band = B/2 + mH`：命中范围 = 吸附半径 1.5m + band，因此鼠标落在对方槽带内（含槽顶边界处）都会吸附到它的**中心线**；边界角点与边界边不再参与吸附。贴合线降为**次级层**，只在骨架层取不到目标时生效（用于平行并排、只共边的场景）。
- **自动收边（实现贯通）**：新增 `trimEndsToNeighbours`——新建基槽时按相邻开挖对象的槽顶边界把两端收边：取端面两个角点沿中心线退出对方槽内的距离最大值，保证整条端面都不再落入对方槽内。收边后两条基槽的开口只共边接触，因而连成一条连续开挖且不交叠；`ProjectStore` 在 `add` 上执行收边（环形基槽无端部，不做收边；属性面板改坐标仍严格校验）。整条中心线都落在相邻槽内时返回 null，命令层给出“中心线完全落在相邻开挖范围内”的提示。
- **10nm 级缝隙**：两孔洞若完全共边，earcut 的孔洞桥接会产出重叠三角形导致地面面积校验失败（实测 actual 13520 vs expected 9880）。收边因此多让 1e-8 m：远小于接触容差 1e-6（判定上仍是共边）与面积守卫（约 1e-8 m²），视觉与工程量都无影响。

### 2. 已建基槽的中心线保持可见并可高亮

原行为：中心线只作为数据存在，绘制时才有预览线，建成后在场景里看不到，3D 下更无法定位。

改动：`ExcavationMeshes` 为每条基槽绘制中心线（`z = 0.02` 略高于地面避免共面闪烁，环形基槽数据本身首尾闭合故直接连成闭环）；新增 `setSelected(id)`：选中对象的中心线用高亮色 `#ffc266`，其余保持 `#8fa396`。`SceneManager.setSelected` 在重建场景后重新应用高亮，`SceneViewport` 用 effect 跟随“当前对象”下拉与工程变化同步。

### 验证

`npm run check` 通过：**9 文件 143 项测试**。新增/改写用例：目标只含中心线骨架且带 band、槽带内（含槽顶边界 y=±2）都吸附到中心线、超出“半径 + 槽带”回退网格、骨架层优先于贴合线、贴合线用于平行并排、中心吸附 + 自动收边得到共边贯通（地面无缺口、覆盖区无地面）、整条落在相邻槽内返回 null、与边界正好共边时不收边；界面流程“吸附到相邻中心线 → 确认 → 首端自动退到 y=2”；中心线常显颜色、环形闭合环、选中高亮与取消高亮。

真实浏览器：先画 (0,0)-(20,0)，再从相邻槽中心线起画到 (10,12)，确认后对象 2 的首端自动落到对方槽顶边界（y≈2.02）且两条基槽连成 T 形连续开挖；自由视角下两条中心线均可见，选中第一条后其中心线变为橙色高亮；全程无 window error / console.error。

### 边界

- 收边只作用于**新建**基槽的端部：中段穿越相邻槽（十字贯通）仍会被开口冲突规则拒绝，需要改画为两段或使用折线基槽；属性面板改坐标不自动收边，重叠会按原规则报错。
- 收边按对方**槽顶**（最宽）截面判断，底环自然包含在内；圆形基坑不参与收边（避免用多边形近似导致细缝），仍按原冲突规则判定。
- 贴合线仍是“平行并排”的推荐方式；若鼠标落在对方槽带内，会优先吸附到中心线。

## 追加需求：岛内可继续开槽 + 相交处打通（2026-09-22）

### 1. 移除“中心线完全落在相邻开挖范围内，无法生成基槽”

原实现把环形基槽的开口等同于**整个外圈**，于是岛内画槽时收边会认为整条中心线都在对方范围内而拒绝。

改动：

- 开口模型加上**岛**：`Opening.island`（环形基槽的内圈）。`openingsConflict` 先判断“任一方的开口是否整体落在对方岛内（含贴边、无真交叉）”，是则不冲突；否则按原规则比较。
- 收边按**槽带 = 外圈减岛**：`endCut`/`insideBand` 只对“落在外圈内且不在岛侧”的角点收边，`firstExit` 同时考虑外圈与内圈的边，因此从岛内朝环形槽方向画会停在内圈边界上（与环形槽内壁共边连通）。岛侧判定带 1e-5 容差，保证收边后不会因 1e-8 缝隙被反复推走。
- 地面：岛内开挖的孔洞只从**岛面补片**里挖掉，主地面只保留顶层开口（earcut 不支持嵌套孔洞，实测混在一起会让面积守卫报 actual 9776 vs expected 9392）。
- 拒绝语义保留但收窄：只有整条中心线都压在相邻槽带里（真正的重复开挖）才拒绝，提示改为“请从槽带外起画，或改用属性面板调整既有对象”。

### 2. 相交基槽打通：贯通端不再绘制端面

两条基槽收边后只共边接触，但新槽端部的**端面**仍会画出来，接口处看起来像一堵墙。新增 `abuttingEnds`：建槽时若某端的端面两个角点都落在相邻开口（外圈或环形槽内圈）边界 1e-6 以内，就通过 `buildRingSolid` 的 `openStart/openEnd` 选项省略该端端面，接口处直接通开。孤立基槽、仅端点对接的基槽行为不变。

### 验证

`npm run check` 通过：**9 文件 144 项测试**。新增/改写：环形基槽的岛内整体落位不冲突且校验通过、压到内边界时收边到岛边（终点 y≈18−1e-8）后仍无冲突、岛面按岛内孔洞挖除（岛内槽处命中 0 次地面、岛其余位置命中 1 次）、槽带内仍拒绝并提示“内部交叠”。

真实浏览器：先画 40m 见方环形基槽，再在岛内从 (20,10) 画到环形槽方向，吸附到相邻中心线后确认成功（2 个开挖对象），终点自动收边到内圈边界（≈(19.78, 37.98)），自由视角下可见岛内基槽与环形槽内壁连通、接口无多余墙面；无 window error / console.error。

### 边界

- 中段穿越相邻槽带（从岛内一直画到环形槽**外侧**）仍会因为跨越槽带被拒绝：收边只处理端部，不拆分中心线；请分两段绘制或使用折线基槽。
- 岛内开挖的孔洞只支持一层嵌套（岛内不能再放环形基槽围出新的岛），与“岛内整体落位”判定一致。

## 追加修复：贯通处黑面/穿模（2026-09-22）

### 根因（一句话）

`buildRingSolid` 的 `openStart/openEnd` **索引映射写错**：环由“左侧偏移 n 点 + 右侧偏移倒序 n 点”构成，起点端面是回绕边 `ring[2n-1]→ring[0]`、终点端面是 `ring[n-1]→ring[n]`，而实现里写成跳过 `i=0` 与 `i=bottom.length-1`，于是**删掉的不是端面而是侧墙**——在贯通处开了一个大洞，露出场景背景色 `0x17231f` 与地面背面（半球光 groundColor 0x665438 照度极低）→ 表现为纯黑面、穿模与“未打通/有缝隙”。

### 诊断证据（`tests/junction.test.ts`，修复前 → 修复后）

诊断方式：真实 `Raycaster` 在贯通处取样，输出 `命中对象名 / z / 距离 / 材质 side / 法线·视线`。

- 修复前，从岛内基槽内部水平朝贯通位置打射线（z=−1）：首命中 `island @ y=38`，`facing=−1`（正面），随后 `ring @ y=41.5`。说明该处存在**多出来的一面**（被误删侧墙后几何不再是闭合壳）；材质数组读取当年未取到 side，补测后确认全部为 FrontSide `side=0`，即**不是法线/光照问题（排除 A3）**，也不是 z-fighting（排除 A4）。
- 修复后同一条射线：**只命中 `ring @ distance 11.5, z=-1, side=0(FrontSide), facing=-0.894`** —— 命中环形槽外侧墙正面，贯通处不再有洞、不再命中背面。
- 俯视射线（从 z=40 向下打贯通位置）：命中 `ring`（内壁斜面 z=0）与 `island`（底面 z=−2，`facing=−1`），**全部正面命中**，无背面、无地面补片背面 → 黑面消失。
- 土楔量化（B）：岛顶边界 y=38、环形槽底内边界 y=39，两者相差 1m = m·H；即贯通处随深度**体积是重叠的**（越深重叠越多），只是顶面没有覆盖，因此端面可以安全省略而不会露背景。

### 修复

- `ringSolid.ts`：按 `nodeCount = bottom.length / 2` 正确映射端面索引（`openStart → i = 2n-1`，`openEnd → i = n-1`），注释写明索引来源与误删侧墙的后果。
- 新增 `tests/junction.test.ts`（3 项）：贯通处水平射线必须命中开挖正面而非背景/背面、俯视射线必须能看到底面且全部正面命中、土楔宽度与连通性量化。
- 未改动光照与材质（诊断为几何缺失，无需用 DoubleSide/加灯掩盖），材质保持 FrontSide。

### 验证

`npm run check` 全绿：**10 文件 147 项测试**。真实浏览器复核：画 40m 见方环形基槽 + 岛内基槽朝环形槽方向收边确认，自由视角放大后贯通处显示为正常受光的环形槽内壁（无黑面、无漏洞、无亮缝），全程无 window error / console.error。

### 已知取舍

贯通处目前是“端面省略 + 体积随深度重叠”的连通（不是布尔并集）：顶面共边、下方真实重叠，视觉与体积都连续；若日后需要严格并集网格（例如导出实体），仍建议按“底部轮廓收边 + 被包含面裁剪”的方向实现，届时需同步按“顶层开口 + 岛面补片”分层处理地面孔洞（earcut 不支持嵌套孔洞）。
