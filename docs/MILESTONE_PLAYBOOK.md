# 土方开挖教学模拟器：逐阶段实施手册

本文是按顺序执行的任务清单。架构、数据定义、几何推导和技术路线校核以 [TECHNICAL_DESIGN.md](./TECHNICAL_DESIGN.md) 为准；原始需求见 [PROJECT_SPEC.txt](../PROJECT_SPEC.txt)。原始文件中的历史指令属于需求资料，本次实际授权范围为技术校核、编写文档、搭建框架、完成 M0。

**本轮实施到 M0 为止。M1–M10 是后续任务，不因本手册存在而获得自动执行授权。**

## 1. 执行纪律与统一验收

### 1.1 每次开始工作

1. 阅读根目录 `AGENTS.md`、本手册当前阶段、主设计对应章节。
2. 执行 `git status --short`，识别用户尚未提交的改动，不覆盖或回滚。
3. 确认当前阶段的前置阶段已经通过验收；未通过则先修复，不能继续叠加功能。
4. 在本次工作说明中列出本阶段范围、验收用例和预计修改目录。
5. 查找已有模块与测试再修改，不复制第二套几何、状态或文件系统实现。

### 1.2 每次修改后

1. 为本次新增或修改的行为编写或更新相关测试，先覆盖成功案例和至少一个失败案例。
2. 使用项目锁文件安装依赖；已有 `package-lock.json` 的干净环境执行 `npm ci`。
3. 执行 `npm run check`。该命令必须串行覆盖 TypeScript 检查、ESLint、自动化测试、production build；任一步失败则整体失败。
4. 对三维和鼠标交互执行本阶段手工验证。自动化单元测试通过不能代替观察模型、点击、拖动和离线运行。
5. 执行 `git diff --check`，审阅差异，再仅暂存本次相关文件。
6. 按根目录铁律创建 Git commit，提交信息描述实际完成内容。分成多次完整改动时分别提交。
7. 记录提交哈希，并按下方格式报告；未经下一阶段授权停止。

阶段报告固定包含：完成内容、新增/修改文件、核心设计说明、已运行测试及结果、已知问题、下一阶段准备、Git commit。测试未运行必须说明原因，不能记为通过；存在阻断项时不得宣称阶段完成。

### 1.3 本轮实施约定

以下数值是工程保护边界，不代表行业规范。以后调整时必须同时修改主设计、验证器、表单提示、加载校验和边界测试。

| 项目 | 本轮约定 |
| --- | --- |
| 单位与坐标 | 长度使用米，面积使用平方米，体积使用立方米；XY 为地面，Z 向上；地面 `z=0`，底面 `z=-depth` |
| 方向角 | 0° 指向 +X，90° 指向 +Y，逆时针为正；业务数据用度，三角函数和 Three.js 适配时转弧度 |
| 位置/节点 | 每个有限坐标满足 `abs(x), abs(y) <= 10000`；生成后的边界也必须处于可支持范围内 |
| 底宽/底长/边长/直径/深度 | 有限数，闭区间 `[0.02, 1000]` |
| 坡比 | 水平距离/垂直距离，有限数，闭区间 `[0, 5]`；`0` 合法 |
| 每段基槽长度 | 严格 `> 0.01`；不通过四舍五入判断 |
| 元素/节点上限 | 一个项目最多 500 个元素；一条基槽 2–200 个节点 |
| Miter | `miterLimit=4`，超限、折返或无效 offset 明确拒绝；MVP 不实现 bevel 回退 |
| 对象相交 | MVP 拒绝顶部开口重叠、包含及边界接触；仅有包围盒相交不等于实际相交 |
| 本体合法性 | 中心线、底部环、顶部环都必须简单；禁止零面积、交叉、穿插和不合法的边坡连接 |
| 历史 | 最多 50 个已完成命令；一次拖动只产生一步；失败/取消/没有变化不产生历史 |
| 网格 | 默认间距 1m；显示开关与吸附开关独立 |
| 地面 | M1 使用完整地面；M2 起根据顶部开口做二维带孔三角化，不做实体 CSG |

容差使用主设计中的统一常量，禁止各模块临时定义互相矛盾的 `epsilon`。范围上限要验证原始参数和派生结果；不允许用无限扩大地面或自动裁掉模型来掩盖异常输入。

### 1.4 跨阶段不可破坏的行为

- 项目保存对象只能包含可验证的 JSON 数据；不得包含 Mesh、材质、DOM、相机、选中状态、草稿线、历史栈或文件句柄。
- 几何失败不覆盖原来的有效对象。先验证候选参数及生成结果，再一次性提交；提示中给出具体字段或原因。
- 从 M2 开始，所有永久项目修改都经过 command seam。M8 才完成完整历史和文件交互，但此前也不得由 React 或 Scene 直接改项目数组。
- `SceneManager` 统一拥有场景对象增删和生命周期；业务核心不依赖 React，React 不拼接几何顶点。
- 每次替换或删除网格释放旧 Geometry/Material；共享资源有明确所有权，不可释放后仍被其他对象引用。
- 表单内允许临时输入 `-`、空字符串等文本，只有有效值才进入项目数据；错误文本不会变成 `0` 或 `NaN`。
- 任何未知异常应保留上次有效项目并显示错误；不吞掉错误、不继续显示假成功结果。

## 2. M0：环境、框架与最小首页

### 前置条件与范围

工作区 Git 已初始化，根目录规则有效，已读完技术设计。只搭建 React + TypeScript + Three.js + Vite 的开发基础，安装并配置基础测试与 ESLint，建立目录，显示最小首页。**本阶段不创建 WebGL 场景，不实现几何、命令系统、文件保存或 Electron。**

### 按顺序执行

1. 检查 Node.js/npm 版本与当前 Vite 所需版本是否匹配；在 `package.json` 和 README 记录支持的开发环境。开发机需要 Node.js 不等于最终用户需要 Node.js。
2. 创建 `package.json`、`index.html`、`vite.config.ts`、React 入口和 TypeScript 配置。TypeScript 开启 `strict`；禁止用关闭检查或大量 `any` 消除错误。
3. 安装 React、React DOM、Three.js；开发依赖包括 Vite、React 插件、TypeScript、类型声明、ESLint、Vitest、Testing Library 和 DOM 测试环境。提交锁文件；不凭空编写版本号或手工修改依赖解析结果。
4. 配置 `dev`、`typecheck`、`lint`、`test`、`test:watch`、`build`、`check`。`test` 必须单次运行并退出，不能进入 watch；`check` 不启动持久开发服务器。
5. 按主设计建立 `src/app/`、`src/components/`、`src/core/`、`src/scene/`、`src/store/`、`tests/` 的各模块目录。空目录用说明文件或 `.gitkeep` 跟踪，不为未来功能写伪实现。
6. 创建 `src/app/App.tsx` 和最小样式：展示中文软件名、教学用途、本阶段状态、下一阶段说明。适配窄屏，控件必须有可读文字。
7. 创建测试初始化文件和首页测试，验证首页核心内容能渲染。添加可在无 WebGL 环境运行的 Three.js 依赖冒烟测试，例如创建向量并验证长度；不要将“页面存在 Canvas”冒充场景验收。
8. 写 README：环境要求、安装命令、脚本用途、当前已完成范围、文档入口。配置 `.gitignore` 排除 `node_modules`、构建产物、覆盖率和本机日志。
9. 执行完整检查，实际启动 `npm run dev` 并确认页面可访问；不能只通过编译推断开发服务器正常。

### 输入输出契约

- 输入：空或仅含需求/规则/文档的工作区、兼容版本 Node.js/npm。
- 输出：可复现安装的前端骨架、锁文件、测试与检查脚本、最小首页、后续模块目录。
- `npm run build` 返回退出码 0，并生成可部署的 `dist/`；`dist/` 不进入源代码提交。
- 本阶段不假称已有可用“新建、保存、绘制”等按钮；有布局占位时明确为未实现。

### 必须验证

- `npm run typecheck`、`npm run lint`、`npm run test`、`npm run build` 全部通过，并确认 `npm run check` 正确组合它们。
- 首页测试能找到“土方开挖教学模拟器”和 M0 状态，不依赖随意变化的 CSS 类名。
- Three.js 冒烟测试可导入核心包与 OrbitControls addon，创建三顶点 BufferGeometry、计算包围盒并释放，且无需创建 WebGL context。
- 开发服务器页面返回成功；实际浏览器显示中文且控制台无运行错误。记录使用端口，避免盲目关闭用户其他进程。
- 新建干净环境从锁文件安装后可以重复检查；如受当前环境限制无法做全量重装，明确记录，不能删除用户已有目录来强行验证。

### 完成门槛与停止条件

全部命令通过、开发页面正常、依赖与目录有文档、相关测试已提交，并创建 M0 Git commit。此时停止，等待 M1 授权。依赖下载失败、Node 不兼容、TypeScript 错误或浏览器白屏均阻断交付，不用跳过检查绕过。

## 3. M1：基础三维场景与完整视角控制

### 前置条件与范围

M0 已通过。实现施工场地、网格、灯光、相机及其控制，不生成基坑/基槽。为避免遗漏总需求，本阶段完成自由、俯视、前视、侧视四种视角，以及重置镜头、网格显示和实体/线框显示模式基础接口。

### 按顺序执行

1. 在 `src/scene/SceneManager.ts` 实现挂载、尺寸变化、单一渲染循环、卸载和销毁；React 场景宿主只负责容器和生命周期调用。
2. 在 `CameraManager.ts` 创建自由视角 `PerspectiveCamera` 和正交视角相机；工程坐标统一 Z-up。自由/前/侧相机 up=(0,0,1)，俯视相机 up=(0,1,0)，避免与视线平行。OrbitControls 的目标、相机 up、重置目标使用同一约定。
3. 在 `GroundManager.ts` 生成中心位于原点的 100m × 100m 地面，放置于 XY 平面；Three.js 默认在 XZ 平面的辅助网格必须显式变换到 XY。
4. 添加基本光照和低对比度 1m 网格，不加载在线材质、模型、字体或第三方 CDN。
5. 在 `components/ViewControls/` 实现四视角、重置镜头、网格显示开关、实体/线框切换。线框切换作用于开挖对象的接口先建立；M1 没有对象时可禁用并解释。
6. 自由视角允许旋转、平移和缩放；俯视保持向下看并禁用旋转。前/侧视保持正交观测，不能因为鼠标拖动悄悄变回斜视。
7. 监听容器变化并同时更新 renderer 尺寸与相机投影；销毁时注销监听、取消动画帧、销毁 controls、renderer 及拥有的资源。

### 输入输出契约

- Scene 输入：容器、只读显示设置、后续对象适配入口；输出：可销毁的场景控制接口。
- 自由视角 `up=(0,0,1)`；俯视从 +Z 看向地面、屏幕上方为 +Y；前视从 -Y 看向原点、屏幕上方为 +Z；侧视从 +X 看向原点、屏幕上方为 +Z。
- 重置按钮恢复当前视角的默认方向/尺度/目标；不删除项目，也不创建项目历史。
- 显示模式和网格显隐不改变几何计算或测量结果。

### 必须验证

- 单元测试：四视角方向正确；改变容器宽高后正交比例不拉伸；重置恢复默认目标。
- 手工：看到完整施工场地和网格；自由视角可以旋转/缩放/平移；切换四视角及重置各 5 次无跳轴、镜像、黑屏。
- 手工：调整窗口大小、隐藏/显示网格、切换线框接口，控制台无异常；地面和网格无明显闪烁。
- 生命周期测试：React StrictMode 挂载/卸载/再挂载不产生两个动画循环和重复事件；连续进入退出场景 10 次后资源数量不持续增长。

### 完成门槛与停止条件

完整检查通过并验证真实 WebGL 画面后提交。相机坐标约定、投影或资源释放尚有问题时停止，不进入 M2。测试环境的 WebGL mock 只验证生命周期，不等于真实 GPU 验证。

## 4. M2：参数化基坑、数据入口与地面开口

### 前置条件与范围

M1 已通过。按 M2.1 方形、M2.2 矩形、M2.3 圆形逐项实现。支持通过明确的演示/属性入口创建和更新对象，正式鼠标放置留给 M5；本阶段开始建立项目数据与命令执行入口，不要求完整历史 UI。

### 按顺序执行

1. 在 `core/model/` 定义有 `version`、`units: 'm'`、`settings`、`elements` 的纯数据项目及四类元素可辨识联合；当前先实现三类基坑。规定稳定唯一 id，禁止通过数组位置标识对象。
2. 在 `core/validation/parameterValidation.ts` 实现有限值、范围、类型、字段和 id 校验，错误包含字段路径和中文原因。
3. 在 `core/commands/`、`store/projectStore.ts` 建立 `dispatch(command): Result<Project>` 入口：读取旧项目、生成候选数据、验证/生成成功后原子提交。M8 的 commandManager 在此入口内部执行并记录命令。暂不实现打开/保存 UI，但测试失败命令不修改数据。
4. 实现 `squarePitGenerator.ts`：先算局部底部/顶部环，再构造底面和四个边坡。上口不加盖板，渲染真实内部；位置和旋转由统一适配处理。
5. 实现 `rectPitGenerator.ts`，复用已经验证的矩形构造函数，但保持方形的单边长数据语义。
6. 实现 `circularPitGenerator.ts`，圆周细分数量遵循主设计。圆周环从同一角度起点生成，底/顶对应顶点一致，不创建重复索引导致零面积三角形。
7. 在 `scene/MeshFactory.ts` 将几何结果转换为场景对象；`SceneManager` 负责替换旧对象和资源释放，底面与边坡可用不同教学色。
8. 实现顶部 opening 轮廓提取及 `GroundManager` 的带孔三角化。地面外环必须覆盖全部开口并留边距；对象添加、移动、旋转、尺寸变化、删除时同步重建地面。
9. 实现对象顶部开口之间的边相交与包含检测。矩形先作世界坐标旋转，再比较轮廓；圆用96边形显示/挖孔，碰撞按主设计使用解析顶半径的圆–圆距离及圆–多边形距离/包含测试，避免漏过内接弦外的细小重叠。
10. 接通参数表单：合法修改立即重建模型；临时非法文本只显示字段错误；拒绝重叠或越界候选并保留上一有效模型。

### 输入输出契约

- 输入：经验证的基坑数据，包括 position、底部尺寸、depth、slope；方形/矩形另有 rotation，圆形不暴露无意义旋转。
- 输出：可生成 Mesh 的几何结果、世界坐标顶部开口、有限的边界范围；精确的数据结构遵循主设计，不能私自增加第二种协议。
- `topLength=L+2Hm`、`topWidth=W+2Hm`；圆形 `r=diameter/2`、`R=r+Hm`。
- 地面覆盖开挖区域以外的 `z=0` 平面；不得用完整不透明地面遮住负 Z 基坑，再宣称已实现开挖效果。

### 必须验证

- 方形：底边 4、深度 2、坡比 0.5，顶边 6；所有底点 `z=-2`，所有顶点 `z=0`。
- 矩形：底长 6、底宽 4、深度 2、坡比 0.5，顶部 8 × 6；旋转 90° 后世界包围范围交换 X/Y 尺寸。
- 圆形：底部直径 4、深度 2、坡比 0.5，底半径 2、顶半径 3。
- 坡比 0：侧壁竖直；底宽 0、深度 0、负数、NaN、Infinity、超上限全部拒绝；错误不会清空已有对象。
- 两个顶边长 6 的方坑中心 `(0,0)` 和 `(7,0)` 合法，`(5,0)` 重叠拒绝，`(6,0)` 接触拒绝；一个开口完全包含另一个也必须拒绝。
- 验证几何 position/normal/index 全有限、索引不越界、无零面积面；正面观察可见槽底，背面剔除设置不会意外隐藏内部。
- 地面测试：孔内不能被地面三角形覆盖；两个分离孔仍可生成地面；移动后旧孔恢复、新孔出现。
- 圆孔相切回归：两个顶半径3的圆心距离为6，连心线方向为 π/96 弧度，仍应拒绝，不能因为96边形采样点错开而放行。
- 手工：三种坑在自由/俯视图可见坑底；前/侧正交视图检查标高、轮廓和方向，侧壁遮挡内部是正确现象，不要求剖切。连续更新参数 100 次资源不持续增长。

### 完成门槛与停止条件

三种基坑、开口地面、参数验证和 command seam 全部通过测试和真实画面验收后提交。三角化失败、开口重叠、模型边界不有限时必须停止该候选更新，不采用 CSG 临时补救或通过透明地面掩盖问题。

## 5. M3：直线基槽

### 前置条件与范围

M2 已通过。本阶段仅支持两个中心线节点，完成底面、左右边坡和两个端面；端面保持垂直，不在中心线两端额外放坡。

### 按顺序执行

1. 在 `trenchValidation.ts` 验证两个有限节点、单段长度及统一底宽/深度/坡比。
2. 在 `trenchGenerator.ts` 计算单位方向 `d=(P2-P1)/L` 与左法向 `n=(-dy,dx)`。
3. 使用 `B/2` 偏移生成底部左右边界、`B/2+Hm` 偏移生成顶部左右边界；底部 Z 为 `-H`，顶部 Z 为 `0`。
4. 按主设计绕序构造底面、两个边坡、起终端面；不创建封口顶面。
5. 输出顶部开口，接入 M2 的地面开孔、重叠校验、资源生命周期与命令入口。
6. 添加最小参数入口，以默认两点创建演示基槽；正式绘制交互留给 M5。

### 输入输出契约

## 6. M4：折线基槽、转角与自交约束

### 前置条件与范围

M3 已通过。只扩展由直线段组成的折线，同一槽统一截面参数。不实现圆弧、贝塞尔、样条、分段不同参数、节点插入删除或 bevel 回退。

### 按顺序执行

1. 扩展 `trenchValidation.ts`：节点数量 2–200、相邻节点不重合、每段长度合格、中心线不自交；非相邻段接触和重复节点也拒绝。
2. 在 `polylineOffset.ts` 实现每段左右平行线；在 `joinSolver.ts` 使用相邻偏移直线交点得到 miter。
3. 对共线同向段做稳定处理，避免平行线求交分母接近零；对折返立即给出可理解的错误。
4. 计算 `miterLength/offsetDistance`，要求不超过 4；offsetDistance 为 0 等特殊情况单独处理。明确角度定义，禁止把“转向角”与“内夹角”混用。
5. 分别构建底部和顶部轮廓，验证轮廓简单、面积非零、连接方向一致；检测 offset 自交及局部短段导致的边坡穿插。
6. 使用完整的连续边界生成槽底和左右边坡；相邻段共享连接位置，不能把每段直槽堆叠当作折线几何。
7. 生成全槽端面和顶部开口，复用地面及其他对象碰撞校验；输出错误必须指明问题节点或线段。

### 输入输出契约

- 输入是 2–200 节点的简单折线；所有段都用同一 B/H/m。
- 输出一条连续的开挖模型与一个有效顶部开口；原地形不做多个段孔洞的布尔并集。
- miter 比率通常为 `1/cos(abs(turnAngle)/2)`；设上限 4 后，接近 180° 的折返必然拒绝。需求中的“内夹角至少 10°”不是充分条件，较大但超出 miter 上限的尖角也拒绝。
- 不做静默节点删除、自动截短、自动改坡比或 bevel 回退；用户数据无效就保留旧模型并提示修正。

### 必须验证

- L 型：`(0,0),(10,0),(10,10)`，B=2/H=2/m=0.5，总长 20；连续槽底及边坡，无尖刺、裂缝或重叠面。
- 多折点：`(0,0),(10,0),(15,5),(25,5)`，总长 `20+sqrt(50)≈27.0710678119`，45° 转角均通过。
- 钝角：`(0,0),(10,0),(15,8.6602540378)` 正常；左右转镜像案例结果对称。
- 共线：`(0,0),(10,0),(20,0)` 正常；折返 `(0,0),(10,0),(0,0)` 拒绝，不产生 NaN。
- 160° 转向：`(0,0),(10,0),(0.6030737921,3.4202014333)` miter 比率大于 4，拒绝。
- 自交：`(0,0),(10,10),(0,10),(10,0)` 拒绝；连续重复节点和非相邻重复节点均拒绝。
- 中心线不交叉但宽槽贴近自身：`(0,0),(10,0),(10,1),(0,1)` 配 B=2/H=2/m=0.5，应因边界/offset 无效拒绝。
- 合法曲折槽与已有开口重叠时仍拒绝；数百个随机有限合法候选生成后 position/normal 全有限，失败结果必须结构化返回。
- 实际浏览器观察 90°、45°、钝角内外侧及线框，不能只检查顶点数组不含 NaN。

### 完成门槛与停止条件

以上用例全部通过，随机/性质测试不出现崩溃，真实画面连续后提交。任何核心几何错误阻断 M5；不靠增加 UI 限制以外的隐式参数修正掩盖算法错误。

## 9. M7：土方量、结果显示与两点距离测量

### 前置条件与范围

M6 已通过。公式全部实现于 `core/calculation/`；UI 只选择数据并格式化。结果标记“预计土方量”，不宣称工程计价精度，不实现角度/高差测量。

7. 若提供全项目合计，仅对已通过不重叠验证的元素求和；不把草稿计入合计，不声称支持相交开挖合并工程量。

### 输入输出契约

- 计算函数接收合法领域数据并返回有限数值，不依赖 Three.js Mesh、React 或格式化字符串。
- 坡比是水平/垂直，m=0 必须退化为棱柱/圆柱；UI 四舍五入不反写原始参数。
- 计算显示中的 m、m²、m³ 不混用；距离在地面 XY 上计算。

### 必须验证

- 直槽 L=20/B=2/H=2/m=0.5：T=4，A=6，V=120m³。
- L 型 `(0,0),(10,0),(10,10)` 同截面：总长 20，V=120m³。
- 多段例 `(0,0),(10,0),(15,5),(25,5)`：V=`6*(20+sqrt(50))≈162.4264068712m³`。
- 原需求展示例 L=25.6/B=2/H=1.5/m=0.5：顶宽 3.5，V=105.6m³。
- 方坑 L=W=4/H=2/m=0.5：V=`152/3≈50.6666666667m³`，显示 `50.67m³`。
- 矩形 L=6/W=4/H=2/m=0.5：V=`212/3≈70.6666666667m³`。此例必须作为防止错误棱台公式回归的测试。
- 圆坑直径4/H=2/m=0.5：r=2/R=3，V=`38π/3≈39.7935069455m³`。
- m=0 时矩形体积 LWH；尺寸统一放大 2 倍、坡比不变时体积变为 8 倍。
- 独立几何交叉验证：在测试副本临时补顶部盖，统一闭合表面的绕序，用有向四面体积分并取体积绝对值。方/矩形与解析公式相符；96段圆坑与解析值相对差 <0.1%；不要在显示模型加盖。
- 测量 `(0,0)` 到 `(3,4)` 得到 5m；同点为 0m；平移/旋转相同点集不改变长度。
- 手工完成两点测量后切换工具，测量辅助资源释放，项目 dirty 与历史不改变。

### 完成门槛与停止条件

公式单元测试、数值性质测试和界面显示全部通过后提交。体积公式与几何约定不一致、单元错误或非法输入生成非有限结果时停止。

7. 实现新建/打开/保存/另存为。可写文件句柄有当前目的地时复用；另存为选择新名称/位置，确认写入成功后更新保存身份；取消或失败保留旧身份和 dirty。Blob 回退只是请求浏览器下载，返回 export-requested，不当作写入成功，也不声称控制了用户保存路径。
8. 新建、打开及离开应用前，对未保存修改给出“保存 / 不保存 / 取消”。选择保存必须等待真实写入成功才继续原动作；保存失败、取消或仅 export-requested 均不继续清空项目。下载回退提供独立“确认已导出”操作，由用户确认文件完成保存后才更新导出快照基线/继续原动作。保存和等待确认期间禁止并发文档修改，以免确认错快照。
9. 浏览器阶段用 `beforeunload` 提供浏览器允许的标准离开提醒；关闭时不能保证异步弹出自定义保存对话框，完整关闭保存流程在 M10 实现。页面内部新建/打开仍用完整三选项对话框。
10. 成功打开/新建后清空历史、草稿、选中和临时测量；打开失败保留整个当前状态。应用 Ctrl+Z/Ctrl+Y 快捷键并沿用焦点/输入法保护。

### 输入输出契约

- 保存项目包含 version/name/units/elements/settings，按主设计处理未知字段；不保存会话对象或 Three.js 实例。
- 项目反序列化是原子操作：不是“先清空，再逐个尝试加载”。无效 JSON 或非法几何不得造成当前工程丢失。
- 返回保存结果需区分 saved、cancelled、export-requested 和外层 Result 失败。只有可确认的写入成功或用户明确确认已导出才更新保存基线；触发 Blob 下载无法得知最终成功/取消，不可自动清 dirty。导出下载与写入已有文件的能力差异必须明确呈现。
- 新建/打开不是在原项目历史里加入一个可撤销命令；它们建立新的项目会话。项目内撤销/重做不恢复历史文件句柄。

### 必须验证

- 含三类基坑、直槽和折线槽的合法项目，保存再打开后参数、id、位置、旋转、设置及预计体积一致；JSON 不含 Scene/Mesh/geometry/material。
- 无效 JSON、version=999、units='mm'、未知 element.type、重复 id、超500元素、超200节点、非法参数、自交和相交开口均拒绝，原项目保持完整。
- 执行创建→改参数→移动→删除，再依次撤销和重做，数据与模型同步恢复。
- 连续执行 51 次独立有效编辑，最多能撤销最近 50 次；撤销后做新编辑，redo 清空。
- 一次包含100次 pointermove 的拖动只撤销一次；取消拖动、失败修改和编辑回原值不占历史。
- 保存 A→修改 B→撤销回 A，dirty=false；重做 B，dirty=true；再次保存 B，dirty=false。
- 未保存时新建/打开：取消则保持当前项目；不保存则执行；保存成功才执行；保存失败/用户取消保存则阻止执行。
- Blob 下载回退：触发导出后 dirty 仍为 true；用户取消浏览器下载后当前文档保留、待执行新建/打开不继续。只有用户明确确认导出完成才将对应快照标记已保存；待确认期间不能并发编辑切换快照。
- 保存后“另存为”成功切换新名称；“另存为”取消不切换；之后普通保存的目标行为符合当前文件服务能力。
- Ctrl+Z/Ctrl+Y 在画布工作，在文本输入框保持文本编辑行为；关闭浏览器标签时实际出现标准未保存提醒。

### 完成门槛与停止条件

文件往返、所有编辑历史、dirty、失败回滚、保存取消和关闭提醒验证通过后提交。任何可能丢失未保存项目的路径都阻断阶段完成，不用“正常路径能保存”代替异常验证。

## 12. M10：Electron 与 Windows Portable 交付

### 前置条件与范围

M0–M9 全部通过后才添加 Electron。完成 Windows 本地桌面、原生文件读写、窗口关闭保存流程和 Portable EXE；优先 x64，其他架构须明确列为额外验证范围。

### 按顺序执行

1. 建立 `electron/main.ts` 与 `preload.ts` 及打包配置；renderer 继续使用已有前端，开发模式和生产本地文件加载路径分别配置并测试。
2. 设置隔离边界：禁用 renderer Node 集成，开启 context isolation；preload 只暴露窄的文件服务接口，不把完整 fs、shell、ipcRenderer 或任意路径执行能力交给页面。
3. 实现原生打开/保存对话框，主进程读写文件；校验 IPC 请求、限制文件大小，renderer 仍通过主设计的 `unknown` 校验完整项目内容。
4. 实现可恢复写入：在目标目录先写临时文件，写完再按支持的平台策略替换目标；失败保留旧工程文件并返回错误。不得只用单元 mock 宣称断电安全。
5. 实现“保存”和“另存为”的当前文件路径语义。打开已有文件后保存写回原文件；新工程首次保存与另存为均弹原生对话框；取消不改变 dirty。
6. 拦截窗口关闭，按保存/不保存/取消流程处理；选择保存时等待成功后关闭，失败或取消保留窗口。使用受控标记防止关闭回调无限循环。
7. 明确禁止非预期远程导航、新窗口和运行时外部依赖；图标、字体、Three.js、应用代码全部随包分发。
8. 配置 production Vite 相对资源路径和 Electron 打包入口，执行完整前端检查、主进程类型检查和打包验证。
9. 生成 Portable EXE，附版本号、说明和校验信息；只打包业务需要的文件，不把源码缓存、开发密钥、测试产物或用户工程混入发行包。
10. 在 Windows 10 与 Windows 11 干净环境或明确标注的独立测试环境，断网执行完整验收；测试机不安装 Node.js，不运行开发服务器。

### 输入输出契约

- 输入：已验证的前端构建与 Electron 主进程/preload、打包配置。
- 输出：无需安装 Node.js、无需登录、无需服务器/数据库/网络的 Windows Portable 应用；项目文件保存在用户选择的本地位置。
- 浏览器文件适配器可保留用于开发；桌面模式使用原生适配器，业务核心不知道当前宿主是浏览器还是 Electron。
- 所有文件错误（权限不足、磁盘满、文件不存在、内容损坏、用户取消）以可理解状态返回；绝不以失败的写入结果更新保存基线。

### 必须验证

- Electron 环境中 renderer 无法访问 Node.js fs，preload 仅有预期接口；无效 IPC 请求被拒绝。
- 从包含中文与空格的路径启动 EXE，在中文路径保存 `教学案例 01.excavation` 并重新打开。
- 测试新建、打开、保存、另存为、关闭三选项及各自取消；关闭时保存失败后窗口仍打开且工程仍在。
- 文件只读/不可写目录/损坏 JSON/未知 version 显示错误；已有工程不会被清空或覆盖为半个文件。
- Windows 10、Windows 11 断网且无 Node.js，启动应用后完成 M9 教学流程，退出后再打开工程；不启动独立服务器，不弹登录窗口。
- production 运行不引用 `localhost` 开发端口，资源没有 `ERR_FILE_NOT_FOUND`，无必需外网请求。
- 至少加载一个包含多类对象的教学案例；检查性能和内存连续编辑是否稳定。若未实测 500 对象上限，必须标注性能尚未验证，不把保护上限当成性能承诺。

### 完成门槛与停止条件

完整测试、真实 Windows 10/11 独立离线验收、文件异常流程和 Portable 实物均通过后，创建最终阶段提交并报告产物位置。只得到 EXE、只在开发机运行或只测试联网开发模式均不算最终 MVP 完成；缺少目标系统时明确列出未完成验收，不伪造通过。
