# M6 选择与编辑（画布点选 + 拖动编辑）

M0–M5 已完成基础场景、三类基坑、折线/环形基槽、俯视绘制与吸附贯通。M6 在此基础上补齐"直接操作已建对象"的能力。

## 本阶段交付

- **画布点选**：`SceneManager.pickAt(clientX, clientY)` 用 Raycaster 对开挖实体求交（Mesh 的 `name` 就是对象 id），点击即选中；忽略中心线、地面与辅助线。
- **选中高亮**：选中对象的**实体**与**中心线**同步换色（实体 `[0xe2cd98, 0xb3833f]`，中心线 `#ffc266`），重建场景后由 effect 重新应用。
- **拖动编辑基槽节点**：选中基槽后，在节点 2m 内按下 → 移动超过 3 CSS 像素才进入拖动 → 拖动中只更新预览线（改后的中心线）→ 松手提交**一次** `update`；失败保留原数据并显示原因。
- **拖动编辑基坑位置**：选中基坑后按下即进入拖动，预览为该基坑改后的槽顶轮廓环，松手提交一次。
- **拖动期间吸附**：复用相邻基槽中心线骨架吸附（排除被拖动对象自身），网格兜底沿用现有设置。
- **拖动阈值**：3 CSS 像素，避免相机旋转/平移被误判为拖动；未越阈值不产生任何命令。
- **面板回读**：属性面板按对象 id 建 key，拖动后重新选择对象即可看到新坐标（面板草稿不随外部改动刷新，属已知取舍）。

## 关键设计

| 关注点 | 做法 |
| --- | --- |
| 稳定回查 | 只用 id 回查数据，Mesh 的 `name` 即 id，不依赖场景遍历顺序 |
| 拖动原子性 | 拖动过程不写工程，只有释放时提交一次 `update`，失败即整体回滚 |
| 拖动与相机 | 阈值 3px 区分"拖动编辑"与"旋转/平移"；拖动只在俯视投影下进行 |
| 预览与提交分离 | 拖动中 `setPreviewPoints` 出预览线，释放后才写数据 |
| 校验一致 | 拖动结果与属性面板编辑走同一条 `update → 校验 → prepare` 链路 |

## 验证

`npm run check` 全绿：**10 文件 150 项测试**。

新增 M6 界面用例：

- 画布点选：绘制后清空选择 → 点击基槽中心线上的点 → 下拉框回到该基槽 id；
- 拖动节点：`pointerDown → pointerMove → pointerUp` 全程只产生 **1 次** `update`，新坐标为 (0,6)；
- 拖动阈值：移动 1px 不提交任何 `update`。

测试环境说明：jsdom 的 canvas 缺少 `setPointerCapture`，已在 `tests/scene-test-kit.ts` 中补桩，避免 OrbitControls 干扰；拾取与拖动均使用真实 `SceneManager`/相机与真实几何。

## 已知取舍与后续

- 面板草稿不随画布拖动刷新（切走再切回即显示新值）；若要实时回显，需要在保持"非法文本不写入模型"前提下改造草稿同步。
- 拖动只支持整节点移动与基坑整体移动；基槽节点增删、基坑旋转拖动、多段批量编辑仍未实现。
- 拖动没有撤销/重做（命令历史属后续阶段）。
